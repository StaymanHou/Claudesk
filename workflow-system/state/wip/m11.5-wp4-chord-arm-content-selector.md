## Problem Statement

The OFF-invariant guard's chord arm selects candidate files by **basename**
(`offInvariantGuard.test.ts:134`, `if (!/hord[A-Za-z]*\.tsx?$/i.test(base)) return false;`), so it
skips `src/components/workspace/panelHost.ts` — the module that owns `panelForChord` and the most
natural home for an M11 Docs chord. This is a **proven** defect, not an inference: M10.9 WP5.2 probe
5b placed an identical ungated workflow chord predicate there and the full guard passed **10/10**,
while the same violation in `docsChord.ts` failed correctly (probe 5a). M11 landing its Docs tab is
precisely the moment this arm must fire, so a guard that cannot see the module it guards is
decorative. **The deliverable is the mutation-proof, not the selector edit.**

## Plan-time audit (done before phasing — findings that changed the plan)

Per the method that paid off three times in WP3, the WBS's task list was audited against the tree
before being followed. Three findings, all verified by command:

1. **The WBS's task 4.1 count is CORRECT** — exactly 12 non-test `*hord*` modules exist, matching
   its enumeration, and `panelHost.ts:78` does export `panelForChord`. Both load-bearing facts hold.

2. **⚠️ A pure content swap REGRESSES reach — the plan must use a selector the WBS did not
   specify.** The obvious content predicate ("reads a chord-shaped keyboard event", i.e. matches
   `metaKey`) **drops `closeTerminalChord.ts`**, which never reads a keyboard event at all — its
   export takes three pre-computed booleans (`{isCloseChord, terminalFocused, canClose}`). Verified:
   it is the *only* one of the 12 with no `metaKey`. Swapping basename→`metaKey` would therefore
   widen reach on one module while silently narrowing it on another, which is a net loss disguised
   as a fix. **The selector chosen instead is the original finding's own suggestion** — files
   **exporting an identifier containing `Chord`** — verified by command to be a **strict superset**:
   it catches all **12** existing modules **plus** `panelHost.ts` (via both `panelForChord` and
   `PanelChordEvent`), with **zero dropped**. 12 → 15.

3. **⚠️ Widening the selector fires a live FALSE POSITIVE that must be fixed in the same phase.**
   The 3 newly-selected modules are `panelHost.ts`, `terminalFontZoom.ts`, and
   `paletteCommands.ts` — and `paletteCommands.ts:77` contains `workflow/archive/…` inside a
   **comment** (a stale doc path pre-dating the 2026-07-28 layout migration). The existing chord arm
   has **no comment stripping**, unlike the wrapper-bypass arm which strips and documents why. So the
   selector change and comment-stripping are one atomic unit: shipping the first without the second
   turns the guard red on prose, which the guard's own comments identify as the failure that gets it
   deleted ("a guard that cries wolf gets deleted by the next person who trips it").

**Baseline:** the guard suite is green at **10/10** before any change.

## Problem Statement

M10.9 needs a single `workflow_features_enabled` setting, **default OFF for everyone including the operator**, that gates the entire workflow-coupled feature class (M11 Docs tab, M12 auto-resume + drive-mode selector, M13 skill buttons) as a set. WP2 builds the gate end-to-end: the persisted field, its Tauri commands, the **frontend consumption seam** every future workflow surface must come through, the user-facing control, and the **OFF-invariant guard test**.

Two things make this more than a boolean. First, per WP1's **Verdict (a) = (iii-b)**, the control's home is a new **`⌘,` Settings panel** rather than the `ProjectPicker` settings strip — and the migration of the 3 existing controls off that strip (then deleting it) is what makes the panel worth building; option (iii-a), panel-without-migration, is the explicitly-rejected "settings in four places" trap. Second, and load-bearing: **M10.9 ships with zero gated surfaces**, so every "is OFF clean?" check passes trivially today and would keep passing even if M11 wired its Docs tab wrong. The guard must therefore assert the *seam contract* mechanically, written against the seam so it survives M11 landing. **A gate without an enforceable seam is a comment.**

Milestone invariant this feature must not violate: **enabling is a pure Claudesk UI-state flip that touches NOTHING in `~/.claude/`** (the operator's skills are live symlinks into the companion repo; a write there could clobber the source).

**Problem statement unchanged** *(§1b re-check, F9b back-loop into P3.2, 2026-07-28)* — the Esc-ordering failure was an implementation defect inside one leaf (a React-batching misuse in the keydown handler), not a shift in what WP2 is for. The gate, its seam, and the OFF invariant are all unaffected; Phases 1–2 remain green and untouched by the fix. **One thing was learned that changes how this feature VERIFIES, not what it builds:** `?raw` source-text guards cannot verify runtime behavior, so a property involving React batching / async / event ordering must be extracted to a pure function and asserted as a value (done — `escDismiss.ts`). Phase 4 should apply the same rule rather than trusting a source guard over migrated control behavior.

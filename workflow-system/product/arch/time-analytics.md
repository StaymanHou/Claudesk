# Time analytics

**Moved to** [`archive/milestone-9-time-analytics/arch-as-built-m9.md`](../archive/milestone-9-time-analytics/arch-as-built-m9.md) on 2026-08-03 (size guard; that dir already held two arch-grade companion docs, so the detail belongs there). **The load-bearing rules stay here:**

- **SQLite is a scoped exception** to the project's no-database rule — time-series aggregation only; see "### Key Decisions".
- ⚠️ **Session END must be MEASURED, not assumed** — 4 signals with a precedence order; a dangling burst inflated a duration to 885 min.
- ⚠️ **A session id is NOT a session: it is one or more LIVES** (2026-09-28). CC's `--continue`/`--resume` (and Claudesk's M12 auto-resume) reuse the id, so `SessionEnd → SessionStart` can repeat under one id. `reclassify::split_lives` splits at each `SessionStart` that follows an end marker; `query::group_events_by_sid` keys buckets per life (`<id>~N` for N≥2 — ⚠️ never `:`, which the frontend's seg id uses). Taking the earliest marker across a whole id had silently dropped 104 sessions' post-resume work (17,206 tool calls). `dangling_sessions` judges the **last** life only.
- ⚠️ **Tile a session's AI half from ONE `AiIntervals` per session** (`AiIntervals::from_events`, then `segments_for_window` per span). Re-deriving tool pairs + subagent pairs per AI-busy span re-parsed every tool row's `meta` JSON once per span — spans × events, 85% of build time, 557 → 97 ms on the 14-day Day window when hoisted (output identical).
- ⚠️ **`time_analytics_query` is `async` + `spawn_blocking`** (2026-09-28). As a sync command it ran on the main thread and froze the whole app for every query. The body lives in `run_analytics_query` so tests drive it without an `AppHandle`.
- **`claudesk export-week [--monday YYYY-MM-DD]`** (2026-09-28, for Neo's weekly report): the Week view as JSON (`claudesk.week-export/1`) on stdout. `lib.rs::run` dispatches it BEFORE the Builder, so there is no GUI. It opens `<app-data>/time-analytics.sqlite` READ-ONLY and never bootstraps. Exit codes: 1 = DB missing or unreadable, 2 = usage; stdout is empty on any failure. It is **unfiltered** by operator ruling. It is built from `query::build_week_ms`, the ms-precision core `build_week` rounds from, so the export and the view cannot drift; `week_total_min` = the `WEEK TOTAL` badge (**three** AI kinds, reasoning included) and `painted_min` = the day label. ⚠️ A read-only open of a WAL DB with no sidecars CREATES `-shm` + an empty `-wal`: "no file changed" is false for any SQLite reader, and "no DATA changed" is the tested property. Module: `time_store::export`.
- ⚠️ **A project's `path` is its sessions' heaviest MODAL cwd**, never the first cwd over every row: reused native `cc-N` ids carry stray rows from other projects (2026-09-28).
- ⚠️ **Aggregate-duration consumers must clip events at `resolve_session_end` FIRST** — the cap lives in the CALLER (`build_viz_session`/`build_metrics`), not the primitives, which return RAW bursts.
- ⚠️ **Mount scope must match data scope** — a component mounted wider than its data window reads stale.
- **`time_tracking_enabled` (default OFF) is the write gate** — and it is the template M10.9's feature gate was modeled on.

## Verification method & instrument traps

- [detector-scored-against-its-own-table-is-circular.md](detector-scored-against-its-own-table-is-circular.md) — Scoring a detector against a fixture its own policy table produced gives 1.000 by identity. Treat a perfect score as a symptom; score against an independent signal.
- [installed-skills-are-symlinks-into-the-mccc-repo.md](installed-skills-are-symlinks-into-the-mccc-repo.md) — Every `~/.claude/skills/` entry is a symlink into the mccc repo, so editing one silently dirties a DIFFERENT git repo; `cp -RL` to dereference and diff that repo's `git status` before/after.
- [git-checkout-no-ops-on-untracked-file.md](git-checkout-no-ops-on-untracked-file.md) — `git checkout` is the wrong mutation-restore in BOTH directions: UNTRACKED → silent no-op (mutant survives); TRACKED-but-DIRTY → reverts to HEAD and DESTROYS uncommitted work. `cp` aside, restore from that, verify by `shasum`.
- [verify-redaction-by-what-remains.md](verify-redaction-by-what-remains.md) — A redaction verified field-by-field verifies nothing; a fixture leaked 4,443 chars via a field the redactor never named while a grep of the covered fields came back clean. Ask "what is STILL unredacted?" over the whole artifact.
- [verify-the-mutation-landed.md](verify-the-mutation-landed.md) — A mutation test must confirm it changed *executable code*, not just that the test ran; `sed -n '<line>p'` the mutated line before believing a pass. A silent no-op looks exactly like a real guard hole and leads to weakening a guard that was fine.
- [behavioral-test-can-still-be-an-equivalent-mutant.md](behavioral-test-can-still-be-an-equivalent-mutant.md) — A landed mutant can survive a behavioral test when both paths give identical observables on its input. Find the discriminating input, and run mutants individually.
- [mutant-survives-because-its-line-never-executes.md](mutant-survives-because-its-line-never-executes.md) — A mutant can survive because its line is NEVER EVALUATED (a gate short-circuits above it), so no input distinguishes the versions. Check the arm is reachable before blaming the test.
- [extracted-machine-needs-a-live-caller-guard.md](extracted-machine-needs-a-live-caller-guard.md) — A pure `plan*` module's own tests cannot see it has zero callers. Guard "every exported `plan*` has a live caller", with the list derived from the exports.
- [whole-app-jsdom-boot-via-tauri-mockipc.md](whole-app-jsdom-boot-via-tauri-mockipc.md) — The REAL `main.tsx`/`pip/main.tsx` boot under jsdom via `@tauri-apps/api/mocks` (`mockIPC` + `shouldMockEvents`, `mockWindows`), no new dep, <1s; precedent `appBoot.test.tsx`. Assert IPC-seeded IDENTITY; it still cannot see a deleted export (that's `check:link`).
- [jsdom-listener-throw-is-silent-in-vitest.md](jsdom-listener-throw-is-silent-in-vitest.md) — Under Vitest jsdom a throw inside a DOM LISTENER is swallowed (window `error` event, no Vitest report, test green); a `setTimeout` throw instead fails the run. Tap `window` `error` to see listener throws.
- [ts-arity-flexible-assignability-hides-a-widened-param.md](ts-arity-flexible-assignability-hides-a-widened-param.md) — Widening a function-TYPE parameter list breaks no implementation (a stub with fewer params stays assignable), so `tsc` + a green suite do NOT prove a newly-required argument is passed. Capture the VALUE in the test double, then mutate the call site.
- [measurement-input-must-be-representative.md](measurement-input-must-be-representative.md) — A measurement's INPUT must exercise the use case or the reading is about the input, not the system; `claude -p "say ok"` never overflowed the pane and produced two confident wrong generalizations about CC's scrollback.
- [skill-usage-count-spans-renamed-command-names.md](skill-usage-count-spans-renamed-command-names.md) — A renamed skill's usage count must sum EVERY historical name (single-name grep under-counted /session-restore by 73%) and match `<command-name>` in text only, never tool_result bodies.
- [raw-guard-substring-must-be-unique-to-its-site.md](raw-guard-substring-must-be-unique-to-its-site.md) — A `?raw` guard must anchor on a substring UNIQUE to the site; `rows: term.rows` also occurs in an unrelated resize path, so hardcoding the nav value left it green. `grep -c` before leaning on a substring.
- [invalid-probe-and-real-hole-look-identical.md](invalid-probe-and-real-hole-look-identical.md) — A guard probe that PASSES means either a real hole or an invalid probe (violation placed in an exempt module) — indistinguishable from the result alone. - [source-guard-blind-to-spread-bindings.md](source-guard-blind-to-spread-bindings.md) — A regex over LITERAL syntax cannot see a binding that arrives SPREAD in (`...searchKeymap`), so the guard passes while that entry has ZERO coverage. - [guard-predicate-completeness-vs-mutation-landing.md](guard-predicate-completeness-vs-mutation-landing.md) — A guard's PREDICATE can be incomplete, so "0 findings" is under-determined (distinct from a mutation that never lands): interrogate the parsed DOM, mutation-test each option individually, attribute each mutant to its own probe.

- [backlog-finding-carries-an-implicit-as-of-date.md](backlog-finding-carries-an-implicit-as-of-date.md) — A backlog finding is true as-of its FILING date; a conditional one ("no consumer until WP3") can be resolved by the passage of the work it names. - [handoff-detail-can-be-wrong-while-its-conclusion-is-right.md](handoff-detail-can-be-wrong-while-its-conclusion-is-right.md) — A handoff's conclusion can be right while a supporting detail is wrong. Verify shipped-state claims against `git tag` / `git log` before building on them.

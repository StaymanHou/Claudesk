- ✅ **WP4 status over the link shipped 2026-11-16** (`82fc64f`, Phase 1 `de02657`). As built: `arch/remote-workspaces.md` §D (origin, routing, the remote install, `--continue`, the close) and §E (the link overlay). ⚠️ **Events route on (origin, cwd)**: a remote event never resolves without its origin, so the close path looks a row up by exact key (`workspace_id_for`). ⚠️ **The remote hook install is STICKY on the link and READ by the workspace** (`remote_hook_warning`): it runs before Up, usually during the picker's open check, when no workspace listens. ⚠️ **An explicit close ENDS the remote session, and a respawn waits for it** (`end_session`, `wait_not_closing`); see the open MAJOR on the quit bound → `# m17-wp4-status-over-the-link`. ⚠️ **"Attached" means the re-attach HELD** (`ATTACH_CONFIRM`), not that its process spawned.
- ✅ **WP5 remote lifecycle shipped 2026-11-17** (`67dec33`, review CRITICAL fix `f7535b4`). As built: `arch/remote-workspaces.md` §E (the lifecycle table). ⚠️ **The open check DECIDES** (one exec + the LOCAL `remote_record`): live + `running` → attach; live + `end-pending` → dialog A; live + unrecorded → dialog B; dead → the two-signal rule from REMOTE signals (Rust returns signals; precedence stays in `predictAction`). ⚠️ **Detach closes the tile** (no Detached tile; reconnect = reopen); a failed detach keeps the tile, since closing it would `cc_kill` = END the session. ⚠️ **`remote_record` writes are serialized** (`WRITE_LOCK`): the quit's parallel `kill_all` must not lose an `end-pending`. ⚠️ The mini's dev account is the personal one, not the admin one (memory `mini-remote-user-is-stayman`, gitignored).
